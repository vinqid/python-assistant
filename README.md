# Помощник по Python

Одностраничный чат для вопросов о Python: разбор кода, ошибок и библиотек. Вход по общему ключу доступа, ответы через Gemini API, история в SQLite. Интерфейс написан на HTML, CSS и JavaScript без фреймворков.

## Запуск

Нужен Python 3.13 или новее. После клонирования репозитория откройте PowerShell в его папке:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

Перед последней командой сохраните в `.env` собственный `APP_ACCESS_KEY` и API-ключ `GEMINI_API_KEY`. Ключ доступа должен содержать 8–255 символов: латинские буквы, цифры, дефис и подчёркивание. Это два разных ключа: первый открывает чат, второй используется сервером для запросов к Google.

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Остановка сервера — `Ctrl+C`. Перезапуск не удаляет историю и действующие сессии.

Для Linux и macOS окружение создаётся командой `python3 -m venv .venv`; далее используется `.venv/bin/python`, а файл настроек копируется через `cp .env.example .env`.

API-ключ создаётся в [Google AI Studio](https://aistudio.google.com/apikey). Доступность моделей, региональные ограничения и квоты зависят от аккаунта. Модель можно изменить через `GEMINI_MODEL`; по умолчанию используется `gemini-3.1-flash-lite`. Если API-ключ не указан, интерфейс и авторизация работают, но при отправке вопроса появляется сообщение о недоступности помощника. Искусственные ответы вместо модели не подставляются.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `APP_ACCESS_KEY` | Общий ключ входа в приложение |
| `GEMINI_API_KEY` | Ключ доступа к Gemini API |
| `GEMINI_MODEL` | Имя модели, по умолчанию `gemini-3.1-flash-lite` |
| `DATABASE_PATH` | Файл SQLite, по умолчанию `data/chat.sqlite3` |
| `COOKIE_SECURE` | `false` для локального HTTP, `true` при размещении за HTTPS |

Переменные окружения имеют приоритет над `.env`. Относительный путь к базе отсчитывается от корня проекта. Папка базы и таблицы создаются при первом запуске. `.env` и содержимое `data/` исключены из Git.

## Устройство проекта

```text
app/
    main.py         приложение, маршруты и обработка HTTP-ошибок
    config.py       загрузка и проверка настроек
    auth.py         проверка сессии и ограничение попыток входа
    schemas.py      входные данные и форматы ответов
    storage.py      сообщения и сессии в SQLite
    llm.py          системный промпт и запросы к Gemini
static/
    index.html      форма входа и чат
    styles.css      оформление и адаптация к узким экранам
    app.js          состояние страницы, валидация и запросы
tests/
    test_app.py     проверки API, авторизации и сохранения данных
    test_llm.py     проверки обращения к Gemini и ошибок провайдера
main.py             точка входа для Uvicorn
```

FastAPI проверяет структуру запросов через Pydantic и отдаёт статические файлы. Страница и API работают с одного адреса: отдельный сервер интерфейса и настройка CORS не нужны. Работа с Gemini отделена от HTTP-маршрутов, а SQL-запросы собраны в одном модуле.

SQLite выбрана для простого запуска без отдельного сервера базы. Вопрос и ответ сохраняются одной транзакцией после успешного ответа модели. Если запрос к модели завершился ошибкой, незавершённая пара не записывается, а текст вопроса остаётся в поле ввода. Даты хранятся в UTC, браузер показывает их в местном времени пользователя.

Чат общий для всех, кто знает ключ. История загружается при входе и обновлении страницы. В запрос к модели входят системная инструкция и текущий вопрос; предыдущие сообщения не передаются. Это позволяет сохранять переписку без реализации контекста модели.

## Авторизация

Ключ передаётся в JSON-теле `POST /api/login`, проверяется только сервером и не сохраняется в браузерном хранилище. Для сравнения используется `secrets.compare_digest`. После входа сервер создаёт случайный токен и устанавливает cookie с `HttpOnly`, `SameSite=Strict` и сроком действия 24 часа. Для размещённого приложения нужен HTTPS и `COOKIE_SECURE=true`.

В SQLite хранится SHA-256-хеш токена, а не сам токен. Сессия привязана к текущему ключу доступа: его замена делает старые сессии недействительными. Выход удаляет сессию на сервере и cookie в браузере. История и отправка сообщений требуют действующей сессии.

После десяти неудачных попыток за пять минут вход с одного IP временно ограничивается. Запросы изменения данных с посторонним `Origin` отклоняются. Пользовательский текст и ответы модели выводятся через DOM как текст; блоки кода отображаются отдельно без исполнения HTML.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/login` | Проверка ключа и создание сессии |
| `GET` | `/api/session` | Проверка текущего входа |
| `POST` | `/api/logout` | Завершение сессии |
| `GET` | `/api/messages` | История общего чата |
| `POST` | `/api/messages` | Отправка вопроса, получение и сохранение ответа |
| `GET` | `/health` | Проверка работы приложения |

Вход принимает `{"key": "ваш-ключ"}`, отправка сообщения — `{"text": "Как работает enumerate?"}`. История и отправка возвращают объект `messages` со списком записей: `id`, `role`, `text`, `created_at`. Успешная отправка возвращает две новые записи.

Коды ошибок: `401` — нет действующей сессии или неверный ключ, `403` — посторонний источник запроса, `409` — предыдущий запрос ещё выполняется, `422` — некорректные данные, `429` — ограничение входа, `502–504` — ошибка модели или временная недоступность сервиса. Ответ с ошибкой содержит строку `detail`.

Интерактивное описание API доступно по адресу `/docs`.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют временные базы данных и подменяют только внешний API модели. Проверяются границы длины ключа и сообщения, пробельный ввод, защищённые маршруты, срок сессии, выход, смена ключа, перезапуск приложения, атомарное сохранение пары сообщений, ограничение входа, тайм-ауты, ошибки квоты и некорректные ответы провайдера. Локальная история при запуске тестов не меняется.

Ручная проверка:

1. При пустом или некорректном ключе кнопка входа недоступна; неверный ключ допустимого формата показывает ошибку.
2. После входа отправьте вопрос о Python. До получения ответа повторная отправка недоступна.
3. Проверьте пустую строку, пробелы и сообщение длиннее 500 символов.
4. Обновите страницу, затем перезапустите сервер: история остаётся.
5. Выйдите и попробуйте получить `/api/messages`: сервер вернёт `401`.
6. Без `GEMINI_API_KEY` отправка показывает ошибку; введённый вопрос сохраняется в поле.

## Что можно доработать

- Передавать ограниченную историю модели для уточняющих вопросов.
- Добавить потоковую выдачу длинных ответов и отмену запроса.
- Загружать историю частями и обновлять её между открытыми вкладками.
- Для нескольких процессов вынести ограничение входа и очередь запросов в общее хранилище. Сейчас приложение рассчитано на один процесс Uvicorn.
- При развёртывании настроить HTTPS, резервное копирование SQLite и мониторинг ошибок провайдера.
